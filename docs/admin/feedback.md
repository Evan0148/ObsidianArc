# 用户反馈

登录用户可以在右上角账户菜单里打开「反馈」，把遇到的问题或者想要的改进写下来；管理员在后台「用户反馈」页面读到全部内容。

反馈是数据库里的行，不是转发到某个邮箱的邮件——「大家说过什么、后来怎么处理的」需要事后还能查，而只落到某一个人收件箱里的反馈，下一任管理员就再也看不到了。

## 用户怎么提交

面板里有四项：

| 字段 | 取值 |
| --- | --- |
| 反馈类型 | `Bug 提交` 或 `建议` |
| 优先级 | `低`、`中`、`高`，这是提交人自己的判断 |
| 标题 | 1–120 字 |
| 内容 | 1–8000 字，输入框特意留得比较大 |

提交后，面板下方会列出这个账号提交过的全部反馈和管理员给出的状态。这也是它不用邮件表单的原因：提交人能看见自己那条到了、后来怎么样了，就不会因为「好像没发出去」再发四遍。

每个账号 24 小时内最多提交 10 条。上限的检查和写入在同一个事务里，先锁住提交人那一行——两个并发请求不会都看见最后一个名额。

## 管理员怎么处理

后台「用户反馈」页面按时间倒序列出全部反馈，可以按状态、类型、优先级筛选，也可以搜索标题、正文和提交人。点开一条会在右侧打开完整正文。

状态只有两个：`待处理` 和 `已处理`，可以来回切换。管理员改的只有状态——反馈正文是别人写下的原话，任何时候都不会被编辑。确实是垃圾内容时才用「删除」，删除不会通知提交人。

这个页面需要 `feedback` 权限，在用户详情的管理员权能里勾选。超级管理员默认拥有全部权限。

## 防刷

默认只有每账号每天 10 条这一道限制。真的被刷过的站点，可以在「安全 → 人机验证场景」里打开「提交反馈时人机验证」——需要先填好 Turnstile 的 Site Key 和 Secret Key。

打开后，提交前要先过一次 Cloudflare Turnstile。验证在写入之前进行，所以没通过的提交不会占用当天的名额。

## 终端

控制台里有同一套能力，可通过网页终端或 SSH 使用：

```
feedback list [--status open|resolved] [--kind bug|idea] [--priority low|medium|high] [--q 关键字]
feedback show <id>
feedback resolve <id>
feedback reopen <id>
feedback delete <id> --yes
feedback send --title "标题" --body "内容" [--kind idea] [--priority high]
```

前五条需要 `feedback` 权限；`feedback send` 是以你自己的账号提交，和面板走同一个接口、同样的上限和校验。没有办法以别人的身份提交反馈。
