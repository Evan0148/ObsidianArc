# 邀请码

后台「邀请码」页面把三件事放在一起，因为它们是同一件事的三个角度：注册要不要邀请码才能进来、邀请码本身怎么生成，以及一个账户自己的邀请码能换来什么。

## 注册模式

页面上只有一个「注册模式」下拉框，实际写的是两个设置项：

| 模式 | `registration.enabled` | `invites.required` | 效果 |
| --- | --- | --- | --- |
| 开放 (open) | `true` | `false` | 谁都能注册；带邀请码也认，邀请码的分组和奖励照常生效 |
| 仅限邀请 (invite) | `true` | `true` | 必须带一个有效邀请码才能注册 |
| 关闭 (closed) | `false` | — | 不接受任何新注册 |

其余的注册规则（邮箱域名白名单、每 IP 注册数、注册频率、模型审核）不受这个开关影响，见[注册与安全](../features/security)和[系统设置](./system-settings)。

「仅限邀请」下，第三方登录（GitHub / Google）如果对应的是一个**还不存在**的账户，不会直接开号：会先停在只剩邀请码这一两项的补充表单上，和邮箱、QQ 缺失时的表现一致，见[第三方登录](./sign-in)。已经绑定过的账户照常登录，不受影响。

## 生成邀请码

在「邀请码」页面点击「生成邀请码」：

| 参数 | 含义 |
| --- | --- |
| 生成数量 | 一次生成多少个，1-500；批量只能生成随机码 |
| 自定义码 | 只在数量为 1 时可填，用于合作方或赞助商链接，见下节 |
| 可使用次数 | 这个码总共能被注册多少次，0 表示不限次数；默认 1 |
| 失效时间 | 从现在起多少天后这个码本身停止可用；不填表示永不失效 |
| 分组 | 用这个码注册的账户会被放进哪个分组；不选则不改变分组 |
| 分组天数 | 选了分组后，成员身份维持多少天；留空第二个数值表示固定天数，两个都填表示在区间内为每次注册各自随机抽取（见下节） |
| 备注 | 给运营自己看的一行说明 |

随机生成的码是 8 个字符，取自不含 `0 1 I L O U` 的字母数字表，界面上以 `XXXX-XXXX` 的形式显示和复制；自定义码是 4-32 位字母和数字，大小写和连字符在录入时会被折叠掉（`abcd-1234`、`ABCD1234` 是同一个码），显示时保持你输入的样子。批量生成的一批码在关闭这个面板后就不会再整批出现，请当场复制。

## 个人邀请码与邀请奖励

在「邀请码」设置卡片里，「允许账户使用个人邀请码」打开后：

- 每个账户会有一个属于自己的邀请码（第一次打开设置里的「邀请」卡片或运行 `me invite` 时自动生成），可以在**设置 → 邀请**里复制码或链接。
- 「每个账户可邀请上限」达到后，这个账户的个人码就不能再用来注册了（返回 `invite_invalid`）；0 表示不限。
- 关闭「允许用户邀请」会同时让已经发出去的个人码失效，还没结算的奖励也按 `disabled` 结算，不只是不再生成新码。
- 「邀请奖励」是每成功邀请一人给邀请人发放的重置卡数量和这些卡的有效天数；奖励数量为 0 表示不发放奖励。

一次邀请要「成功」，被邀请人需要：账户处于活跃状态、没有被注册审查模型限制、并且在本站要求邮箱验证时已经完成验证——不要求验证的实例在注册那一刻就结算，要求验证的实例会在完成验证后再结算一次。注册时被审查模型限制的账户，限制解除后由后台每 10 分钟一次的例行清理补上结算（只追溯最近 30 天内的邀请）。以下情况邀请人拿不到奖励，会被如实记录而不是悄悄跳过：

| 记录原因 | 触发条件 |
| --- | --- |
| `same_ip` | 被邀请人的注册 IP 和邀请人的注册 IP 相同，或和邀请人当前任意一个在线会话的 IP 相同 |
| `limit` | 邀请人已经达到「每个账户可邀请上限」 |
| `disabled` | 结算时「邀请奖励」数量为 0，或「允许用户邀请」已关闭 |
| `inviter_gone` | 邀请人账户在结算前已被删除 |
| `inviter_disabled` | 邀请人账户在结算前已被禁用 |

奖励发放后，邀请人会收到一条通知，点开跳转到**设置 → 邀请**。奖励只会发一次：即使注册和邮件验证两次都触发了结算检查，也只有第一次真正生效。

## 合作方 / 赞助商链接

给合作方一个好记的固定链接，用自定义码：生成时数量填 1，自定义码填一个好记的词（例如 `PARTNERX`），可使用次数填 `0` 表示不限次数，分组选要给的用户组，分组天数按需要填一个区间——比如 `3` 到 `7`，表示每个通过这个链接注册的账户，会被随机分到 3 到 7 天中的某一天数的试用，具体天数在注册那一刻确定并各自独立，不是所有人都一样。

链接的形式是 `站点地址/register?invite=` 加上码本身，例如 `https://你的域名/register?invite=PARTNERX`。把这个链接交给合作方，或者只给他们那个码，让对方自己拼。

要看这个码带来了多少人、每个人分到了多少天，在邀请码列表里点开这个码，或者在终端用 `invite uses PARTNERX`。合作方码没有所有者，不计入任何账户的个人邀请奖励。

## 撤销

点开一个码，「撤销」会让它停止接受新的注册；已经通过它注册的账户，其分组成员身份和已经发放的奖励都不受影响，不会被追回。撤销是幂等的——对已撤销的码再撤销一次不会改变原来的撤销时间。

列表可以按「来源」（管理员生成 / 用户个人）和状态（有效 / 已用完 / 已过期 / 已撤销）筛选，也可以按码本身或所有者用户名搜索。

## 权限

管理这些接口需要新的 `invites` 后台权限，在「用户」页面编辑管理员的权限列表里授予。只有 `invites` 权限的管理员也能改本页的设置：`invites.*` 和注册方式用到的 `registration.enabled`，但改不了其他任何设置；账户自己的邀请码（`GET/POST /api/profile/invites*`）不需要任何后台权限，任何登录账户都能读写自己的那一份。

## 终端

```bash
invite list [--kind admin|user] [--status active|used_up|expired|revoked] [--search 文本]
invite create [--count N] [--code 自定义码] [--uses N] [--days N | --expires YYYY-MM-DD] [--group 分组] [--group-days N|N-M] [--note 备注]
invite revoke <码|id> --yes
invite uses <码|id>
invite stats
me invite
me invite regenerate --yes
```

需要 `invites` 权限；`me invite`、`me invite regenerate` 任何登录账户都能用，只作用于自己的码。`--expires` 写的日期当天全天有效（按服务器时区），到第二天零点失效；`--uses 0` 表示不限次数。示例：

```bash
invite create --count 20 --uses 1 --note '9 月活动批次'
invite create --code PARTNERX --uses 0 --group Trial --group-days 3-7 --note 'aff 合作'
invite revoke PARTNERX --yes
invite uses PARTNERX --json
me invite regenerate --yes
```

## 注册失败

仅限邀请模式下没有带邀请码，返回 `invite_required`；邀请码不存在、已撤销、已过期、已用完，或者它的个人码所有者账户已被禁用或删除，一律返回 `invite_invalid`——不区分具体原因，避免让人靠试探邀请码本身猜出更多信息。自定义码格式不对是 `invite_code_format`，和已存在的码重名是 `invite_code_taken`（都在生成时校验，不是注册时）。运营方关闭了个人邀请码开关后再调用 `POST /api/profile/invites/regenerate`，返回 `invites_disabled`。
